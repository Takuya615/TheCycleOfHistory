# 「歴史の宮殿」発表スライド 作成指示書

*本ドキュメントは、AIにスライド（pptx）を生成させるための指示書である。*

---

## 0. 前提条件

| 項目 | 内容 |
|---|---|
| サービス名（仮） | 歴史の宮殿 |
| 想定聴衆 | 顧客・一般向け（サービスを知らない人への体験デモ） |
| 発表時間 | 3〜5分・簡潔（1項目＝1〜2スライド目安、テキストは最小限） |
| 全体トーン | エンタメ・体験重視。堅い理論説明より「やってみたら記憶できた！」という驚き・楽しさを前面に出す |
| 構成フレーム | AIDMA（Attention → Interest → Desire → Memory → Action） |
| 参照資料 | [service_design_document.md](../service_design_document.md)（サービスの理論的基盤）、[theme_freedom_challenges_and_whitelist.md](../theme_freedom_challenges_and_whitelist.md)（MVP範囲の参考） |

**デザイン方針**：文字を詰め込みすぎない。1スライド1メッセージ。可能な箇所は図解・イラスト・簡単なインタラクション演出（「やってみましょう」の間を作る）を優先する。

**AIDMAのMemory（記憶）段階の方針**：Memoryは情報量を増やす段階ではなく、「1つのキーワードだけを持ち帰ってもらう」段階として設計する。本プレゼンでは、そのキーワードを **サービス名「歴史の宮殿」** に固定する。スライド8〜10では、説明を足すよりも「歴史の宮殿」という名前そのものを繰り返し・大きく・印象的に見せることを優先し、聴衆が細部を忘れてもこの一語だけは記憶に残る構成にする。

## 1. スライド構成（AIDMA対応）

### スライド1｜Attention：課題提起
- **メッセージ**：「歴史を覚えられないでお困りではありませんか？」
- **内容**：年号や人名を並べて暗記しても定着しない、という多くの人が共感する「あるある」を投げかける。
- **トーン**：共感を誘う軽い問いかけ。深刻になりすぎない。

### スライド2｜Attention：権威性の提示
- **メッセージ**：「記憶の宮殿は記憶力の世界大会でも使われている本物のテクニック」
- **内容**：場所法（Method of Loci）＝「記憶の宮殿」が、世界記憶力選手権の上位入賞者が実際に使う手法であることを紹介し、「これを使うとこんなことができる」という期待感を作る。
- **補足根拠**：Maguire et al. (2003) など、場所法の有効性を示す研究がある（[service_design_document.md](../service_design_document.md) 4-1節）。ただし引用は軽く触れる程度で、academic色を出しすぎない。

### スライド3｜Interest：ビフォア体験①
- **メッセージ**：「まずは何もなしで、12個のランダムな動物を覚えてみましょう」
- **内容**：動物12種を**イラストは使わず、動物名のテキストのみ**で提示する。あえて視覚的にイメージしにくくし、「言葉だけで覚える難しさ」を体感させるのが狙い。
- **表示形式**：12個を1つずつ順番に表示するアニメーション（スライドイン・フェードイン等）を付け、発表者が1匹ずつ読み上げながら表示できるようにする。全部同時表示はしない。
- **動物リスト**：種類・順番ともにランダムに構成する（後述スライド6とは異なるリスト・異なる順番にする）。
- **演出メモ**：発表全体の中で最も参加型・体験型のパート。時間を計るなど、ライブ感を出す。

### スライド4｜Interest：失敗の共有
- **メッセージ**：「難しいですよね？！」
- **内容**：多くの人が半分も思い出せないという「できなさ」を明るく共有し、次の解決策への期待を高める。
- **トーン**：失敗を笑いに変える。深刻な指摘ではなく「ですよね〜」という空気。

### スライド5｜Interest→Desire：解決策の提示
- **メッセージ**：「記憶の宮殿（ボディー法）のやり方は...」
- **内容**：想像上の建物ではなく「自分の体」を記憶の場所として使う手法（ボディー法）を解説。足先から頭頂へ、身体の部位に記憶したい情報を順番に貼り付けていくイメージを図解する。
- **補足**：具体的な感覚（温度・質感・重さなど）と結びつけることで記憶に残りやすくなる、という点を一言添える（[service_design_document.md](../service_design_document.md) 4-2節「感覚による符号化」）。難しい専門用語（符号化特異性原理、等）は使わず「感覚と結びつけると忘れにくい」程度の平易な表現にする。

### スライド6｜Desire：アフター体験
- **メッセージ**：「さっそく試してみよう！！もう一度12個のランダムな動物を記憶にチャレンジ」
- **内容**：スライド3と同様、動物名の**テキストのみ**を12個提示し、今度はボディー法を使って身体の部位に紐づけながら記憶してもらう。
- **表示形式**：スライド3と同じく、1つずつ順番に表示するアニメーションを付ける。
- **動物リスト**：スライド3とは**種類・順番ともに異なる**新しいランダムリストにする（使い回さない）。これにより「覚え方（型）は同じでも、対象が変わっても通用する」ことを暗に示せる。
- **演出メモ**：スライド3との対比が最大の見せ場。表示フォーマット（テキストのみ・1つずつ表示）は揃えつつ、中身の動物は変えることで「型の再現性」を体感させる。

### スライド7｜Desire：効果の実感
- **メッセージ**：「覚えやすさが全然違うでしょう？」
- **内容**：スライド3・6の結果を比較（例：思い出せた数の違いを軽く示す）。聴衆自身の体感を根拠にするため、データや研究の話は最小限でよい。
- **トーン**：達成感・驚きを共有する明るいトーン。

### スライド8｜Memory：応用への想像
- **メッセージ**：「もしもこれを歴史の暗記に活用できればどうなるでしょうか？」
- **内容**：動物という「点」の記憶に成功した体験を、歴史という「時系列の流れ」の記憶に応用するとどうなるか、聴衆に想像させる問いかけ。次スライドへの橋渡し。

### スライド9｜Memory：サービスの提供価値
- **メッセージ**：「記憶の宮殿（ボディー法）で歴史を覚えられればこんなに便利」
- **内容**：歴史の出来事を古い順に足先→頭頂へ身体にマッピングし、各出来事をAIが自動生成した「感覚描写」（肌に触れる質感・温度・匂いなど）として体に貼り付けていく体験を紹介。
  - AIが入力された歴史テーマに応じて感覚描写を自動生成する点を明確に伝える（技術的な仕組みの核心）。
  - 「知っている」ではなく「体験したことがある」記憶になる、という価値を一言で表現する。
- **トーン**：ここも引き続きエンタメ・体験ベース。技術的な設計思想（[service_design_document.md](../service_design_document.md) 4-3, 4-4節の「認知的ひっかかり」「隣接する感覚のにじみ」）は裏側の話として、スライド上では触れるとしても1行程度に留める。
- **Memoryの布石**：説明の最後に「歴史の宮殿」というサービス名を大きく提示し、聴衆の記憶をこの一語に収束させ始める。

### スライド10｜Action：行動喚起
- **メッセージ**：「いますぐ簡単に自分の好きな歴史を覚えよう。本サービスを使えばすぐに適当な『歴史の宮殿』を作れます！」
- **内容**：好きな歴史テーマを入力するだけで、AIが自動的にその人専用の「歴史の宮殿」（身体マッピング＋感覚描写のセット）を生成できることを伝え、今すぐ試したくなるCTA（Call To Action）で締める。
- **トーン**：明るく背中を押す、行動を促す締めくくり。
- **Memory×Action**：スライド上で「歴史の宮殿」という名前を最も大きく・目立つ形で表示する（ロゴ的な扱い）。聴衆が他の詳細を忘れても、このサービス名だけは覚えて帰れることを最終ゴールとする。

## 2. 共通の注意事項（スライド生成時）

- 各スライドはテキストを詰め込まず、キーメッセージ＋最小限の補足＋ビジュアル（イラスト・図解・写真等のプレースホルダー）で構成する。
- 専門用語（符号化特異性原理、望ましい困難、等）は聴衆向けスライドには出さず、平易な言葉に言い換える。裏付けが必要な場合は発表者のトークで補足する想定とし、スライドには載せない。
- スライド3と6は**表示フォーマット（動物名テキストのみ・1つずつ順番に表示するアニメーション）は揃える**が、**動物の種類・順番は毎回ランダムに変え、両スライドで重複や使い回しをしない**。
- Memory（記憶）段階では情報を増やさず、「歴史の宮殿」というサービス名1語に集約することを最優先する。スライド8〜10を通じて、聴衆の記憶に残すのは細部の仕組みではなく名前そのものである。
- 全体を通して「体験→驚き→納得→行動」という感情の流れを重視し、理屈より体感を優先する。
